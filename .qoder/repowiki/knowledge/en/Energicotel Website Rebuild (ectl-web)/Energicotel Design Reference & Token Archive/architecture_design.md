Static, non-executable reference material organized into three sibling areas:
- `html/`: full-page HTML dumps (one file per page: home, about, board, contact, gallery, management, news_list, news_detail_bond, unit_engineering, unit_gas, unit_power, unit_solar) captured from the live WordPress + Elementor site; each file is a self-contained snapshot including inline CSS, Elementor widget markup, and external resource links.
- `screenshots/`: raster captures of every page at desktop/tablet/mobile breakpoints, named `<page>_<device>.png`.
- `tokens.json`: machine-readable analysis output with a top-level `pages` map mirroring the `html/` files; each page entry carries `url`, `meta` (title, description, og_image, favicon, image counts, dom_nodes), an `elements` map keyed by semantic role (`body`, `h1..h6`, `paragraph`, `link`, `button_primary`, `nav_link`, `card_image`, etc.) with resolved computed styles (`color`, `background_color`, `font_family`, `font_size`, `line_height`, `border_radius`, `width`, `height`), plus frequency histograms (`top_text_colors`, `top_backgrounds`, `top_font_sizes`).
- `tokens_summary.md`: human-readable summary derived from `tokens.json`, listing Elementor global CSS variables (`--e-global-color-*`, `--e-global-typography-*`), site-wide frequency tables for colors/fonts/sizes/weights/radii, key element specs, contact data found, and font stylesheet URLs.

Dependency direction is one-way: `tokens_summary.md` summarizes `tokens.json`; both are derived artifacts from the live site — there is no build step or code that consumes them.
