Top-level orchestrator for a Django project split into three concerns: `config/` provides the project root (settings per environment via `DJANGO_SETTINGS_MODULE`, URL routing, WSGI entry), `django_apps/` holds feature packages (core, team, units, news, gallery, contact) that register themselves with the project's URLconf, and `design_reference/` is a committed Phase-0 archive of the source WordPress site used to derive tokens consumed by the Tailwind theme. The root wires them together through `manage.py` (defaulting to `config.settings.dev`), `requirements/{base,dev,prod}.txt` pinning shared dependencies, `.env.example` for env vars, and `static/js/vendor/` for pinned htmx/alpine builds. Front-end assets flow from `theme/static_src/src/styles.css` (Tailwind v4 `@theme` block) compiled via `python manage.py tailwind build`.
